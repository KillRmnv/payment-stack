# LIMITS

- `003_add_amount_minor` с `DROP COLUMN amount` уже необратима (не expand/contract) — считаем базовым состоянием. Откат кода до pre-003 невозможен; дальше только backward-compatible миграции + forward-фиксы `004_...`.
- Нет Vault HA и ротации секретов на лету (только ручной `deploy/vault/rotate.sh <env>` без потери данных); прод-Vault — за рамками. Dev-Vault эфемерен: при пересоздании/потере токена секреты надо seed'ить заново.
- Нет blue-green/canary — rolling `up --wait` + smoke; даунтайм на миграциях с lock возможен секунды. Автооткат в `deploy.sh` откатывает `api worker outbox mock-provider` на smoke/readiness-фейле, но не при нездоровых DB/Rabbit; build/migrate-фейлы и bind-mount конфиги nginx/monitoring автоматически не откатываются. Deploy/rollback/rotate/restore сериализованы `flock`; dirty tree блокируется, кроме `ALLOW_DIRTY=1`.
- Alertmanager доставляет алерты в локальный `alert-sink` (webhook) и всегда шлёт `Watchdog` — это dead man's switch для цепочки. Внешнего pager/email/Slack нет; для реальной эксплуатации замените URL в `monitoring/alertmanager.yml`. `AlertSinkDown` ловит падение sink, но если умрёт сам Prometheus, внешнего heartbeat тоже нет.
- DB-down и broker-down теперь видны через `api_db_up`/`api_broker_up` и алерты `DbDown/BrokerDown`; `MetricsStaleBusiness` остаётся дополнительной, но не единственной защитой.
- Dashboard `monitoring/dashboard.json` — 10 панелей (success-rate/pending/oldest/dlq-rate/queue depth/outbox/DB-broker/latency/statuses/backup-age). Success-rate исправлен (transfers-only, без `clamp_min(...,1)`); Grafana в compose нет, импорт ручной, datasource uid `prometheus` не провижинится.
- Backup age/size и срок сертификата mock-provider отдаются метриками (`backup_*`, `provider_cert_expiry_seconds`) и алертами. Disk usage, PITR/offsite/encryption дампов по-прежнему не сделаны.
- Хост с VPN/файрволом может не доставать до published-портов (host→bridge режется): для таких стендов — `scripts/smoke-net.sh` и диагностика только `docker compose exec` изнутри сети. Deploy/rollback/restore сами переключаются на in-network smoke, если нет `curl` или `python3`.
- Нет e2e нагрузки, chaos-тестов, SBOM-подписей образов.
- Registry GC/retention тегов не настроены; pipeline собирает и сканирует образы (Trivy image) на PR и push, но не делает `trivy fs/config`, secret-scan или подписи; `make scan` остаётся локальной командой. CD deploy запускается на self-hosted runner только при настроенных `STAGE/PROD_DEPLOY_ENABLED`, путях и labels; deploy собирает тот же SHA локально, а не тянет registry digest. Без runners/vars deploy jobs skip.
- Cron бэкапа — `deploy/backup.cron` на хосте (`0 * * * * make backup ENV=stage`), retention `KEEP_DAYS=14`, бэкапы в `backups/<env>/` с правами 0600. Нет шифрования дампов, offsite-копии, WAL/PITR и автоматической проверки restore; `--apply` делает safety-backup и верификацию в temp DB (это удваивает место/время).
- Версия в ZIP стабильна (генерированный `VERSION`), но переход существующего стенда с проекта `deploy` на `payment-stack-stage` не автоматизирован: старые контейнеры/тома остаются, новый проект стартует с пустыми томами. Для миграции используйте `PAYMENT_STACK_PROJECT=deploy PAYMENT_STACK_RUNTIME_ENV=runtime.env` или вручную переносите тома.
- `reporting-ui` из стартера удален как дрейф — вернуть при нужде отдельным overlay.
- Retry с экспоненциальным backoff в consumer (блокирует один воркер на `min(2^retry,16s)`): осознанный компромисс однопоточного prefetch=1 — без backoff короткий чих провайдера сразу дает DLQ. Экспоненциальный backoff с jitter через DLX/TTL — только при росте нагрузки, здесь не делаем.
- `worker_dlq_published_total` — Counter опубликованных в DLQ (бывший `worker_dlq_depth` Gauge врал после ручной чистки DLQ). Глубина DLQ теперь берётся из RabbitMQ Prometheus plugin; replay — `scripts/dlq-replay.sh` (по умолчанию невалидный poison не трогает, `--all` — трогает; аудит-лога реплея нет).
- Outbox закрывает dual-write и поддерживает publisher confirms, но `SENT`-строки не чистятся автоматически (retention — вручную), `transfer_outbox` хранит один payload на перевод, а API без `Idempotency-Key` при `REQUIRE_IDEMPOTENCY_KEY=false` снова допускает клиентские дубли. `outbox`-сервис — отдельный контейнер; при его падении API продолжает принимать переводы, но они ждут в outbox до восстановления.
- Мигратор теперь ждёт advisory lock и падает по таймауту, проверяет checksums и делает pre-migration backup; остаются ограничения: нет down-миграций, checksums фиксируют дрейф только после первого прогона, а `transfers`/`transfer_outbox` не имеют retention/партиционирования.
- Нет authN/authZ на API (любой, кто достучался до proxy, может создать/прочитать перевод), TLS на ingress не делается (за proxy выше по уровню), DB/Rabbit-пользователи приложения — admin/superuser, worker монтирует весь volume с приватным ключом mock-provider. Это осознанные границы тестового стенда, но не production-профиль.
