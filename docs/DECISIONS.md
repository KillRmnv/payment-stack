# DECISIONS

- Base compose + `compose.stage/prod.yml` (только дельты, подключаются через `-f` в `Makefile`/`deploy.sh`/`rollback.sh`/`pipeline.yml`). Base ничего не публикует наружу кроме proxy; stage открывает `15672/9090` только на `127.0.0.1`, prod — ничего лишнего.
- Версия не зависит от `.git`: `scripts/version.sh` (`APP_VERSION` → git SHA → `VERSION` → `nogit-UTC`). `package.sh` по умолчанию (`WITH_GIT=1`) включает `.git` и требует clean tree, поэтому версия после распаковки берётся из SHA; `WITH_GIT=0` кладёт в ZIP сгенерированный `VERSION` для standalone-архива. Успешный deploy/rollback пишет `.deploy-state-<env>` и append-only `.deploy-history-<env>` (timestamp, version, image IDs) — это даёт ручной откат даже после успешного «плохого» релиза.
- Stage/prod — разные compose-проекты `payment-stack-<env>`, разные `runtime.<env>.env` (0600) и `backups/<env>/`. Раньше оба env были проектом `deploy` с одним `runtime.env`, поэтому prod-деплой переиспользовал stage-тома и перезаписывал секреты.
- Пины `tag@digest` (сняты `buildx imagetools inspect` 2026-11-20): воспроизводимость > удобство обновлений. Обновление = тег+digest парой.
- Multi-stage `builder→runtime`, `USER 10000`, `.dockerignore`, `requirements==` — образы меньше, нет apt-дрейфа, не-root.
- Мигратор one-shot + `pg_advisory_lock`, убран из entrypoint. При занятом локе ждёт до 30s, затем падает (не skip); `lock_timeout=30s`/`statement_timeout=10min`; `deploy.sh` делает pre-migration backup. `schema_migrations.checksum` ловит изменение уже применённой миграции. Forward-only: откат кода не трогает схему (003 с DROP уже опасна, дальше только expand/contract).
- Deploy/rollback/rotate/restore сериализованы `flock` на `.deploy-lock-<env>`. Deploy отказывается собирать dirty tree (`ALLOW_DIRTY=1` — осознанный escape); в `.deploy-history` пишутся image IDs. Auto-rollback по smoke/readiness откатывает `api worker outbox mock-provider`; при нездоровых DB/Rabbit код не откатывается, конфиги nginx/monitoring не версионируются.
- Vault fail-fast: пустой секрет = `exit 1`, сервисы не стартуют с пустыми паролями. `runtime.<env>.env` в git не коммитится (только `runtime.env.example`, см. `.gitignore`), генерируется из Vault с `umask 077`/0600; `--strict` отбрасывает плейсхолдеры. `seed.sh` без `--force` не затирает существующий ключ; ротация без потери данных — `vault/rotate.sh` (ALTER + rabbitmqctl + seed --force), `seed --force` напрямую — только с пониманием десинка pgdata и только если DB/Rabbit-пароли не меняются.
- `down -v` запрещен (`make no-destructive` + CI-чек). Деплой идемпотентный: build образов внутри `deploy.sh` (лечит stale-теги), `db-auth-check` после build/up db и **до migrator** (десинк pgdata/пароли — понятный FATAL, не молчаливый 503), smoke host/in-network в `deploy.sh` и `rollback.sh` + `LAST_GOOD_VERSION` автооткат (код `api worker outbox mock-provider`, не схема).
- Reverse-proxy резолвит api через переменную + `resolver 127.0.0.11 valid=10s`: после пересоздания api IP меняется, статичный upstream давал бы вечный 502. `/metrics` закрыт на edge (`404`) — наружу только бизнес-API, Prometheus ходит в `api:8000` внутри сети.
- Vault dev-root токен стабилен на env (экспорт → `.vault-token-<env>` → генерация): смена токена пересоздает Vault и стирает in-memory секреты.
- Один pipeline `.github/workflows/pipeline.yml`: `test` (lint/test/compose/config validation) → `build-scan-push` (3 образа GHCR full+short SHA, Trivy gate) → `deploy-smoke` (ubuntu-latest: clean deploy + idempotency/alert/restore/outbox) → `deploy-stage` → `deploy-prod`. Deploy stage/prod запускаются только на self-hosted runners `stage`/`prod`, при `vars.STAGE_DEPLOY_ENABLED`/`PROD_DEPLOY_ENABLED`, с environment approval для prod; stage после деплоя гоняет `alert-selftest` и `smoke-idempotency`. Без настроенных runners/vars stage/prod jobs skip; deploy-smoke всё равно доказывает HEAD.
- API больше не публикует в RabbitMQ напрямую: `transfers` и `transfer_outbox` пишутся одной транзакцией. `Idempotency-Key` обязателен по умолчанию (`REQUIRE_IDEMPOTENCY_KEY=true`), уникальный ключ + `request_hash`; повтор с тем же телом → 200/тот же id, другое тело → 409. Отдельный `outbox`-сервис публикует с publisher confirms, `FOR UPDATE SKIP LOCKED`, backoff и gauge `outbox_pending/oldest`; backfill возвращает старые `PENDING` в outbox.
- Worker: `PoisonMessage` и `LookupError`→DLQ сразу, retriable→retry x5 с экспоненциальным backoff `min(2^retry,16s)` (окно ~31с: без него ретраи пролетают за мс и короткий чих провайдера = DLQ, проверено учением) →DLQ. `x-retry-count` парсится защищённо внутри try: `abc`/`None`/отрицательное значение → poison в DLQ, а не вечный redelivery. Ответ провайдера валидируется (`payout_id` + терминальный `COMPLETED|FAILED`), иначе `ProviderProtocolError`→DLQ, чтобы не писать произвольный статус в БД. Consumer однопоточный prefetch=1 по дизайну, sleep — осознанный компромисс, зависший провайдер виден через алерты. Метки `processed/duplicate/poison/retry/dlq`, `DLQ_PUBLISHED.inc()` (`worker_dlq_published_total` Counter вместо врущего Gauge) на каждой публикации в DLQ, `verify=<ca-bundle>` вместо `verify=False`, `request_id=transfer_id` в логах; retry/DLQ publish идут через publisher confirms, при неподтверждённой публикации исходное сообщение не ack’ается.
- Health: `/health` проверяет DB+broker параллельно, у каждого свой таймаут 2.5s; `/ready` проверяет только DB, потому что при outbox API может принимать переводы при упавшем RabbitMQ. Метрики `api_db_up/api_broker_up` (обновляются health/ready/metrics), `pending/oldest_pending`, `api_transfers{status}`, latency histogram на POST+GET всех исходов; при недоступности БД gauges не трогаем, но `api_db_up=0` даёт `DbDown`. Worker/outbox имеют `/health` (реальная готовность consumer/relay) и `/metrics` на том же порту; reverse-proxy `/healthz`, Prometheus/Alertmanager `/-/healthy`, alert-sink `/health`. Важное следствие: `MetricsStaleBusiness` не ловит DB-down (серии остаются), это зафиксировано в LIMITS; DB-down диагностируется через `/health` и рост oldest pending.
- Алерты с порогами: `down 2m` (не флэп), `DbDown/BrokerDown/poison/dlq 2m`, `p99>1s 5m` (transfers), `ApiSuccessRateLow`, `PendingHigh`, `oldest_pending>300s 5m`, `MetricsStaleApi/MetricsStaleWorker absent(up{job}==1) 5m` + `MetricsStaleBusiness absent(gauges) 5m` (молчание ≠ ок), `RabbitMQDown/OutboxDown/AlertSinkDown/WorkerNotReady/OutboxNotReady 2m`, `OutboxStale/OutboxPendingHigh/OutboxPublishErrors/OrphanPending`, `BackupMissing/BackupStale`, `ProviderDown/ProviderFailing/ProviderCertMissing/ProviderCertExpiry`. `DlqNonEmpty` — глубина `rabbitmq_queue_messages{queue="transfers.dlq"} > 0`; `scripts/dlq-replay.sh` умеет dry-run и сброс retry-заголовков. Alertmanager доставляет в локальный `alert-sink`; `Watchdog` всегда горит, а `make alert-selftest` отправляет уникальный `SelfTest` и проверяет его в sink (старый Watchdog не даёт ложный зелёный). Внешний pager — замена URL.
- Бэкап `payments` + sha256 + retention `KEEP_DAYS=14`, `backups/<env>/`, права 0600 (`deploy/backup.cron` на хосте). Restore: checksum обязателен; `--verify-only` идёт в temp DB с `ON_ERROR_STOP`; `--apply` сначала верифицирует, делает safety-backup, затем DROP+dump в одной транзакции (`--single-transaction`), migrator, api/worker, smoke. `make restore-selftest` проверяет, что битый дамп и дамп без checksum отвергаются.
- Сдача без секретов: `scripts/package.sh` собирает ZIP, исключая `runtime*.env/.vault-token-*/.deploy-state-*/.deploy-history-*/backups/.metrics`; по умолчанию включает `.git` (clean tree required) и проверяет token-like строки в source и истории, а также утечки по именам файлов. `WITH_GIT=0` собирает standalone ZIP без `.git` с `VERSION`.
- Clean-machine деплой: `deploy-smoke` (ubuntu-latest) реально делает `make deploy`, `smoke-idempotency`, `alert-selftest`, `restore-apply-selftest` и `outbox-drill` на HEAD; это доказательство Level 2, не заменяющее self-hosted stage/prod.
- Reverse-proxy healthcheck проверяет `127.0.0.1`, а не `localhost`: в контейнере `localhost` может резолвиться в `::1`, а nginx слушает IPv4-only.
- Restore `--apply` удаляет все таблицы public-схемы в той же транзакции, а не два захардкоженных имени: иначе `004`/`transfer_outbox` делает restore нерабочим. Добавлен `restore-apply-selftest`.
- Учения не должны менять версию: `outbox-drill` экспортирует `APP_VERSION` из `.deploy-state`/`version.sh` и после trap проверяет образы и health.
- Ротация секретов — maintenance window с остановкой app-сервисов и best-effort rollback старых значений; zero-downtime rotation не заявляем.
- `alert-selftest` отправляет уникальный `SelfTest` через Alertmanager API: старый Watchdog в sink не может дать ложный зелёный. `alert-sink` работает non-root и пересоздаётся при деплое.
- Суммы форматируются целочисленно; `MAX_AMOUNT_MINOR=10^12`; выше — 400. API не получает RabbitMQ в `depends_on`, чтобы стартовать при упавшем брокере.
